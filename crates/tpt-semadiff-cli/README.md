# tpt-semadiff-cli

[![Crates.io](https://img.shields.io/crates/v/tpt-semadiff-cli.svg)](https://crates.io/crates/tpt-semadiff-cli)

The `semadiff` command: a structural, AST-aware diff for source files, directory trees and git
revisions. It compares two versions of a file by their syntax trees rather than by lines, so a
reformatting or a rename shows up as what it is, not as every line that happens to differ.

It is built for reviewing large blocks of AI-generated code, where line diffs are noisy and
easily mislead a reviewer.

```
File: src/main.rs
┌─ Function: calculate_metrics (Lines 40-85) ──────────────────────┐
│ [UPDATE] Changed `sum` to `acc`                                  │
│ [INSERT] Added `if metrics.is_empty() {`                         │
└──────────────────────────────────────────────────────────────────┘
```

The engine lives in [`tpt-semadiff-core`](https://crates.io/crates/tpt-semadiff-core) and the
interactive viewer in [`tpt-semadiff-tui`](https://crates.io/crates/tpt-semadiff-tui). This
crate is the command-line layer that ties them together.

## Installation

### Prebuilt binaries

The installers are generated by cargo-dist and are published with each GitHub release.

```
# macOS and Linux
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/tpt-solutions/tpt-semadiff/releases/latest/download/tpt-semadiff-cli-installer.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -c "irm https://github.com/tpt-solutions/tpt-semadiff/releases/latest/download/tpt-semadiff-cli-installer.ps1 | iex"
```

### From crates.io

```
cargo install tpt-semadiff-cli
```

The binary is installed as `semadiff`. Building needs a Rust toolchain and a C compiler,
because the tree-sitter grammars are compiled from C sources.

## Quick start

```
semadiff OLD.rs NEW.rs                  # boxed per-function summary
semadiff git-setup                      # make semadiff your git difftool (once)
semadiff --rev origin/main...HEAD       # every supported file this branch changes
semadiff doctor                         # check git, the difftool and the grammars
```

## Usage

```
semadiff OLD NEW                       # boxed per-function summary
semadiff OLD_DIR NEW_DIR               # every changed file in two directory trees
semadiff --rev origin/main...HEAD      # every file this branch changes
semadiff --out unified OLD NEW         # classic line diff
semadiff --out json OLD NEW            # structured report for CI
semadiff --out markdown --rev A..B     # Markdown for a pull request comment
semadiff --ignore-formatting OLD NEW   # comment-only edits report zero changes
semadiff --summary llm OLD NEW         # plain-English summary via the Anthropic API
semadiff --max-functions 3 --rev A...B # CI gate: fail when more than 3 functions change
semadiff --tui OLD NEW                 # interactive viewer
semadiff doctor                        # check git, the difftool and the grammars
```

### Input modes

- **Two files.** `semadiff OLD NEW` compares the two files. The language comes from the file
  extension.
- **Two directories.** `semadiff OLD_DIR NEW_DIR` pairs up the supported files in both trees
  by relative path. A file that exists on one side only is compared with an empty file.
  `.git` directories and symbolic links are skipped.
- **Git revisions.** `--rev` asks git which files changed, then compares each one.

| Spec | Old side | New side |
| --- | --- | --- |
| `--rev REV` | `REV` | the working tree |
| `--rev A..B` | `A` | `B` |
| `--rev A...B` | merge base of `A` and `B` | `B` |

Renames are followed. Changed files in unsupported languages are skipped, and their count is
printed on stderr.

- **Git's external diff.** When git calls semadiff with its seven-argument external-diff form,
  it is accepted, and the exit status is always `0`, as git requires.

### Languages

| Language | Extensions |
| --- | --- |
| Rust | `.rs` |
| Python | `.py` |
| JavaScript | `.js`, `.mjs`, `.cjs`, `.jsx` |
| TypeScript | `.ts`, `.mts`, `.cts` |
| TSX | `.tsx` |
| Go | `.go` |

Other files are compared as plain text, in the line-diff fallback.

### Options

| Option | Default | Meaning |
| --- | --- | --- |
| `--out text\|unified\|json\|markdown` | `text` | Output format |
| `--rev REV` | | Compare git revisions instead of files |
| `--engine chawathe\|zhang-shasha` | `chawathe` | Matching engine. `zhang-shasha` is exact but slow on large files |
| `--ignore-formatting` | off | Strip comments before diffing, so comment-only edits report zero changes. Whitespace never affects the result |
| `--color auto\|always\|never` | `auto` | Colour text output. `auto` colours only a terminal and honours `NO_COLOR` |
| `--summary rules\|llm\|off` | `rules` on a terminal, otherwise `off` | Add a plain-English summary above the changes |
| `--max-functions N` | | CI gate: exit `1` when more than `N` distinct functions changed |
| `--fail-on-unparseable` | off | CI gate: exit `1` when a changed file cannot be parsed |
| `--tui` | off | Browse the changes in the interactive viewer. One file pair only |
| `-h`, `--help` | | Help |
| `-V`, `--version` | | Version |

Summaries are offline by default in a terminal, so you see them without asking. When output is
piped or redirected, they are off unless `--summary` is given.

### Output formats

- **`text`**: boxed per-function summary, with `[INSERT]`, `[DELETE]`, `[MOVE]` and `[UPDATE]`
  annotations and line numbers. Coloured on a terminal.
- **`unified`**: a classic line diff, for tools and reviewers who want one.
- **`json`**: a structured report. In directory and revision modes it is a `{"files": [...]}`
  envelope. The schema is in
  [docs/json-schema.md](https://github.com/tpt-solutions/tpt-semadiff/blob/master/docs/json-schema.md).
- **`markdown`**: a report ready to paste into a pull request comment.

### Exit status

| Code | Meaning |
| --- | --- |
| `0` | No semantic changes |
| `1` | Changes found, or a CI gate tripped |
| `2` | Usage or I/O error |

## Subcommands

### `semadiff git-setup`

Writes the git configuration that makes semadiff the difftool. Run it once. It is idempotent,
so running it again changes nothing.

- `--global` (the default) or `--local` chooses where the config is written.
- `--external` also sets semadiff as git's external diff, so `git diff` uses it.
- `--uninstall` removes the configuration again.

Configuration is read and written through `git config`.

### `semadiff completions <shell>`

Prints a shell completion script for `bash`, `zsh`, `fish`, `powershell` or `elvish`.

```
semadiff completions powershell >> $PROFILE
```

### `semadiff doctor`

Checks the environment: that git is available, that the difftool config is in place, that the
`ANTHROPIC_API_KEY` is set when the LLM summary is wanted, and that each built-in grammar loads.

## CI

Two CI gates make semadiff a review step rather than only a report.

```
semadiff --max-functions 3 --rev origin/main...HEAD   # fail when more than 3 functions change
semadiff --fail-on-unparseable --rev origin/main...HEAD
```

A pull request that changes too much logic in one go can be stopped before review. A file that
cannot be parsed can be treated as a failure instead of being skipped silently.

Full setup for GitHub Actions and other CI systems:
[docs/ci-enforcement.md](https://github.com/tpt-solutions/tpt-semadiff/blob/master/docs/ci-enforcement.md).
A runnable example script is in
[examples/ci/](https://github.com/tpt-solutions/tpt-semadiff/tree/master/examples/ci).

## LLM summaries

`--summary llm` asks the Anthropic API for a plain-English summary of the changes. It needs
`ANTHROPIC_API_KEY` in the environment. If the key is missing or the request fails, semadiff
prints a notice on stderr and falls back to the offline rule-based summary. It never fails the
diff because of the summary.

## Git integration

`git-setup` covers the usual case. For the manual configuration, and for using semadiff as
the external diff driver, see
[docs/git-integration.md](https://github.com/tpt-solutions/tpt-semadiff/blob/master/docs/git-integration.md).

## Limitations

- Matching is heuristic. Large restructurings can pair nodes differently from what a person
  would expect. The summary rules are less sensitive to this than the box output.
- Only the six built-in grammars are supported. Other files fall back to a line diff.
- Adding or removing an optional semicolon is a real token change, and is reported.

See [docs/usage.md](https://github.com/tpt-solutions/tpt-semadiff/blob/master/docs/usage.md)
for the full reference.
